 1. 회의 개요
--------------------------------------------------------------------------------
- 성격  : 한국교통안전공단(TS) 발주 예정 "AI 기반 검사업무 시스템 구축 +
          기능개선" 사업의 입찰 공고에 대한 제안 준비사(KCS)의 사전 방문 질의
- 장소  : 공단 김천 본사 (제안 발표도 김천 현장 발표, 원격 화상 불가)
- 참석  : TS 직원 4명 (궤도·삭도 담당 / 도면 사업 담당·간사 / 과장급 /
          배석 직원) + KCS 인력 2명 (영업 담당 / 기술·개발 담당)

--------------------------------------------------------------------------------
 2. 사업 구조 (TS 설명) — v2에서 확정
--------------------------------------------------------------------------------
- **3개 부서 공동 발주** (v2 재전사로 확정). 운영 시스템 3개, 사업별 PM 3명
  요구와 정합.
- 검사 영역: 궤도·삭도 + 주차·튜닝·기계기구
  · 궤도·삭도: 안전관리계획서를 검사원이 수기 검토 → AI 검토 전환 (OCR 미적용)
    — 현장 검사 후 업체 사무실에서 서류 전수 검토하는 프로세스 부담이 도입 배경
  · 주차·튜닝·기계기구: 도면에 OCR(비전) 적용 필요
- 오픈 일정: 각 사업이 걸려 있어 우선순위 없음 → 빅뱅(동시) 오픈
- 과업 성격: AI 신규 + 기능개선 + SI 혼재

 3. 주요 질의응답 (KCS 질문 → TS 답변)
--------------------------------------------------------------------------------
① OCR 인식률 기준
   → 제안요청서에 90% 수준으로 명시 예정.
   → 공단 보유 OCR 제품: ⚠️ 전사본 상충(v1 "없음" / v2 "있음") — 문맥상
     '없음(제안사가 제안)' 우세이나 질문지로 재확인 필요.

② GPU/파인튜닝 인프라
   → 공단에 H200 GPU 보유. 타 부서(해외사업)와 공유 + 별도 관리부서 존재
     → 상시 제공 불가, "하루 몇 시간" 식 시간제 협의.
   → 공유 여유 정도는 전사본 상충(⚠️ "크게 어렵지 않다" vs "허락 어려울 것")
     — 질문지로 확정 필요.
   → VM/게스트OS 분할·스펙 협의는 사업부서 아닌 전산 주관처(정보처)와 협의.
     제안사 물리 장비 반입 방식 아님.

③ 개발·테스트 서버
   → 공단에 개발 서버 없음 — 운영 서버에 바로 반영하는 문화 (유지보수 직원이
     업무시간 후 반영·롤백). 나머지 두 시스템은 하루 중단돼도 업무 지장 없음.
   → 테스트 장비 제공 여부는 TS가 추가 확인 예정.
   → KCS는 개발→테스트→스테이징 절차·형상관리·고객 컨펌 배포 원칙과 PMS
     (협업) 서버 반입 가능성을 설명.

④ 상주 인력
   → TS 요구: 사업별 메인 PM 1명씩 최소 3명 상주 (업무 파트 PL과 별개).
     상주 공간(랩실·상면) 제공.
   → KCS: PM 3명으로는 부족, 개발자 다수 투입 계획. 과거 우정사업본부 나주
     프로젝트 228명 투입 경험 언급. 원격지 개발 곤란 인식 공유.

⑤ 카카오 알림톡·웹 접근성 비용
   → 알림톡 건당 발송비의 사업비 포함 여부: ⚠️ 전사본 상충 — 즉답 없이 "별도
     확인" 흐름이었으므로 미확정. 질문지 필수 항목.
   → 웹 접근성: 대국민 서비스 확인. 신규 시스템의 별도 인증 심사(장애인연합회
     경유) 필요 여부는 TS도 즉답 불가 → 차장/과장 경유 메일 회신 예정.

⑥ AI 모델(SLM) 선정
   → TS는 선호 모델 없음, 제안사 제안에 위임 ("모든 업체에 동일 — 알아서 잘").
   → KCS 설명: 외산 오픈소스(라마·퀜·젬마)는 무상이나 기술지원 없음 / 국산
     솔트룩스 루시아는 지원 가능하나 비용 발생 + 온프레미스 어플라이언스 장비
     수반. 제안 시점과 평가 시점의 기술 변화도 고려 요소.

⑦ 컨소시엄/하도급 (KCS 최대 관심사)
   → KCS 사정: 법인 단위 중소기업이나 지주사(홀딩스) 산하 12개 계열사 소속으로
     공고의 **상호출자제한 문구**(v2 확정)에 걸림 → 단독 참여 희망했으나
     주사업자를 앞세운 컨소(개발은 KCS 전담) 구도 검토 중. 회의에서 확답을
     얻지는 못함.
   → TS 입장: 하도급 조항은 "기능개선을 하도 주겠다는 업체가 많아" 열어둔 것
     (허용이지 의무 아님). 옆 건물 4층에 공단 전체 시스템 유지보수 업체가
     상주하며 수년간 소규모 개선을 해와서, 이들과의 협력이 사실상 필수.

⑧ 인터페이스/유지보수(SM) 협조
   → 연계 개발 수요 다수. 전달로는 부정확하므로 유지보수 측과 직접 소통 권장.
   → UI 등 소소한 변경은 유지보수 직원들과 "최대한 협조" 사전 합의 완료.
     큰 건은 수주사가 직접 개발. 소스코드 미제공 우려는 "신경 안 써도 된다".

⑨ 기타
   → 공단 실무진(기계·전기·자동차 전공)은 IT 전문성이 낮음을 수차례 언급 —
     RFP도 전산부서(AI혁신처·정보관리처·정보운영처) 지원을 조금 받아 맨땅에서
     직접 작성. 기술 질의는 반드시 메일(질문지)로.
   → SM 업무 요청 창구는 업무(사업)별 담당 체계.

 4. KCS 회사 소개 (TS 질문에 대한 답변)
--------------------------------------------------------------------------------
- 1974년 한국컴퓨터 태생, 지주사(홀딩스) 분사 구조. 계열 12개사 중 6개 상장 +
  6개 비상장 (v2 정정).
- 주력: 금융 IT — 오라클·OGG·Tandem·계정계·무중단 서비스, HP 제품군 납품,
  카드사 등 금융권 다수 + 나라장터 조달·공공 수행 경험
- 계열사: 한네트(편의점 ATM), 로지시스(현금수송), 부동산 계열 등
- 제안 부서는 SI(개발) 전문 부서

 5. 결정 사항 및 액션 아이템
--------------------------------------------------------------------------------
[합의/결정]
- 컨택포인트: TS 실무 담당자(직원2)로 일원화
- 질의는 서면(메일 질문지) 원칙 — 기술 질의는 구두 불가, 메일에 모두 녹일 것
- KCS의 TA(기술 아키텍트) 대동 재방문 진행 — 차주 목표
  (시스템 구성도는 대외비로 반출 불가 → 현장 열람)
- 재방문 배석: 정보화 처장급은 소집 곤란 → 일정 담당자 중심으로 조율

[KCS 액션]
1. 질문지 메일 송부 + 방문 후보 일정(복수) 제시 → "이 날 중 언제 괜찮으신지"
2. 차주 TA 담당자 대동 재방문 → 시스템 구성도 등 현장 확인
3. 컨소 구도(주사업자 선정) 확정 및 제안 준비 착수
4. ⚠️ 상충 3건(OCR 보유 / GPU 여유 / 알림톡 사업비) 질문지에 재확인 항목으로
   명시

[TS 액션]
1. 접수된 질문지에 대한 부서별 답변 취합 (차장/과장 경유)
2. 알림톡 비용·웹 접근성 심사의 사업비 반영 여부 내부 확인 후 회신
3. 테스트(개발) 서버 제공 가능 여부 확인
4. 재방문 일정 회신 (과장은 차주 금요일 오전까지 가능)

--------------------------------------------------------------------------------
 6. 리스크 / 특이사항 (제안 관점)
--------------------------------------------------------------------------------
- 상호출자제한 문구로 인한 참여 자격 이슈 — 회의에서 확답 미획득. 컨소 구도의
  적격성 여부를 공식(서면) 확인 필요. ★최우선
- GPU(H200) 시간제 공유 → 파인튜닝 일정 리스크. 학습 자원 스펙·가용 시간을
  질문지에 구체 명시 필요.
- 개발 서버 부재 + 운영 직반영 문화 → 제안서에 개발/테스트/스테이징 환경 자체
  구성안과 품질 통제(형상관리·검수 배포) 방안 포함 필요.
- 발주처 IT 전문성 낮음 → 요구사항 해석 리스크. 서면 질의로 근거를 남길 것.
- 알림톡 등 종량 비용의 사업비 포함 여부 미확정 → 원가 산정 시 별도 반영 대비.
- 상주 최소 3명(사업별 PM) + 김천 상주 → 인건비·체류비 반영. 지방 상주 인력
  수급 리스크(나주 사례 참조).
- SM(유지보수 업체) 협력 의존도 높음 → 착수 초기 SM 협업 체계 합의 필요.

※ v2 요약은 faster-whisper large-v3 재전사 + v1(medium) 교차 검증 기반입니다.

  화자 구분은 내용 기반 추정입니다(음성 화자분리 미적용).
